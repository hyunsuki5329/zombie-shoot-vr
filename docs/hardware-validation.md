## 2. 첫 회차: 조작과 표시

현재 정상 연결되는 Quest Pro + Virtual Desktop 환경으로 진행한다. 제공된 기존 설정은 High/90Hz/270Mbps/SSW Always enabled였다. 이는 조작 시험의 환경 기록이며 72Hz 성능 인수 결과로 사용하지 않는다. 시작 날짜·시각과 실제 적용된 설정, 변경 여부를 [결과 양식](templates/hardware-session-result.md)에 기록한다.

1. BossCrawlerMenuLab을 실행한다. 시작 준비8초 뒤 전투가 시작된다. 왼손 X(PC F6)로 정지, 왼손 Y(PC F7)로 새 도전을 시작한다. 재도전 후 왼손 그립은 놓았다 다시 잡는다.
2. **T04/T05 외형·양손 제한**: 시작 직후와 재도전 후 양쪽 눈에서 총·탄창의 재질/크기/위치가 자연스러운지, 손이 총에서 과도하게 벗어나거나 탄창 삽입을 가리지 않는지 확인한다.  오른손 그립을 놓아도 총이 오른손에 유지되는지 확인한다. 오른손만으로 발사되지 않고, 왼손 앞부분을 잡으면 발사되며, 트리거를 누른 채 왼손을 놓으면 즉시 멈춰야 한다.
3. **T06/T07 재장전**: 앞부분 그립 해제 → 총 아래 탄창에서 새 그립 입력으로 탈거 → 놓아 버리기 → 왼쪽 허리에서 새 그립 입력으로 공급 → 그립을 유지하며 삽입 → 놓았다 앞부분 다시 잡기 → 발사. 잔탄 교체10회, 빈 탄창 교체10회를 따로 센다. 삽입 직후 앞부분을 잡기 전에는 발사되지 않아야 한다. ROUNDS 표시는 앞쪽 상태판에서 확인한다.
4. **T12 정지/재개**: X로 정지하면 전투·스틱 이동·낙하 탄창은 멈추고 머리·손 추적은 유지되어야 한다. 정지 중 왼손을 앞부분에서 멀리 옮긴 후 Resume을 선택한다. 예전 잡기 상태로 발사되면 실패다. 메뉴를 누른 트리거도 놓았다 다시 눌러야 발사된다.
5. **T15 메뉴/HUD**: 오른손 포인터로 Settings/Back/Resume을 선택하고 양쪽 눈에서 오른팔 HP·웨이브·처치 수를 읽는다. 조준·삽입 자세에서 총구·삽입구·표적을 가리면 당시 손 위치를 기록한다. Settings의 Move/Turn 변경 뒤 Back만 누르면 정지를 유지하고 Resume으로 재개한다. 재실행 후 설정 유지도 확인한다.
6. **P10 피드백**: 발사는 총성+오른손 진동, 성공한 삽입은 삽입음+왼손 진동이어야 한다. 정지 중에는 전투 소리가 멈추고 재도전 시 소리가 중복되지 않아야 한다. 들리지 않음·지연·너무 큼/약함을 따로 기록한다.

한 번 성공한 항목을10회 성공으로 쓰지 않는다. 막힌 단계는 실패 또는 미실행으로 남겨도 된다. 먼저 이 회차의 결과를 보내면 조작 결함을 수정한 뒤 나머지를 검증할 수 있다.

## 4. 로그를 함께 남기는 방법

PC PowerShell에서 다음을 실행한다. 게임이 이미 실행 중이면 먼저 정상 종료한다. 로그 수집을 위해 기존 정상 VR 연결 방법을 바꿀 필요는 없다.

```powershell
Set-Location -LiteralPath 'D:/Unity Project/Zombie Shoot VR'
& './scripts/Start-VrDiagnostics.ps1' -Build UserAudioMenuLab -FrameTimings
```

실행 전 경로 확인만 하려면 `-CheckOnly`를 추가한다. `-Build`를 생략하면 이전 MenuLab이 선택되므로 새 외형 시험에서는 위 인수를 유지한다. 로그는 아래 폴더에 생성된다.

`C:/Users/User/AppData/LocalLow/DefaultCompany/Zombie Shoot VR/Diagnostics`

같은 이름의 `.jsonl`(객체·상태)과 `.vrft`(원시 프레임)가 한 쌍이다. 날짜/시각과 파일 이름을 적고 세션 종료 후 두 파일을 보존한다. PC에서 앱 창을 정상 종료한 뒤 기록을 분석한다. 작업 관리자 강제 종료·헤드셋 연결 해제만으로 정상 footer 기록을 기대하지 않는다. Player.log도 필요하면 **다음 게임 실행 전에** 별도 폴더로 복사한다.

`C:/Users/User/AppData/LocalLow/DefaultCompany/Zombie Shoot VR/Player.log`

새 결과 파일 이름을 지정해 분석한다. 아래 자리표시는 실제 파일 경로로 바꾼다.

```powershell
python -B scripts/analyze_vr_diagnostics.py '실제-기록.jsonl' --output '새-객체요약.json'
python -B scripts/analyze_vr_frame_timings.py '실제-기록.vrft' --output '새-프레임요약.json' --csv '새-프레임.csv'
```

실행 방법과 지표 의미는 [성능 문서](../Zombie%20Shoot%20VR/Docs/performance.md)를 따른다. 분석에 실패해도 원본 로그를 삭제하지 말고 오류와 함께 알려준다. 기록 경로를 이 채팅에 알려주면 분석을 이어갈 수 있다. 화면 녹화는 선택 사항이며 녹화 여부를 기록한다.

## 5. 성능 시험은 별도 회차

위 조작이 안정된 뒤 VD를72Hz·SSW Disabled로 설정하고 해상도·코덱·비트레이트와 네트워크 조건을 고정해 별도 기록한다. 기존90Hz·보간 켬 자료와 합치지 않는다. 설정 적용 후 다시 실행하고 실제 적용 상태를 확인한다.

지금 UserAudioMenuLab에서는 로그 생성·GPU 유효 표본 존재·종료 기록 여부를 짧게 점검할 수 있다. 이것은 실제 방/강의실 성능 시험이 아니다. CPU전체 시간은 대기를 포함하므로 CPU 작업12.5ms 판정으로 사용하지 않으며, GPU0·빈 표본은 측정 불가다. CPU 작업 지표·VR 런타임 대조가 완료되기 전 성능 통과를 선언하지 않는다.

최종 두 맵 각각 워밍업2분 뒤 빈 맵3분, 일반 전투3분, 최대 동시 수3분, 지속 플레이30분을 수행한다. 재도전·맵 전환도 각각10회다. CPU/GPU 각각 p95≤12.5ms, p99·끊김·객체 상한·RAM/VRAM 추세·계측 켬/끔 조건을 [T17 계획](vr-fps-project-docs/08-test-plan.md)에 따라 기록한다. 정지 시간이 포함된 로그 길이만으로30분 플레이를 인정하지 않는다.
