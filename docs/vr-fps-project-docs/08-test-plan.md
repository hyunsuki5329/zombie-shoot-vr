# 테스트 계획과 완료 판정

2026-10-17 사용자 승인: 맵별 지속 플레이 시험은 기존30분에서 약5분으로 변경한다. 분석 시 각 맵의 실제 플레이 약300초와 정상 종료·오류·객체 상한을 확인하며, 장시간 안정성 검증으로 확대하지 않는다. 기존72Hz CPU/GPU 측정 및 재도전·맵 전환 횟수 기준은 별도이며 이번 답변으로 면제되지 않았다. 분석기의 thirty_minute_sample_span은 이전30분 참고 필드이므로 새5분 기준 실패로 해석하지 말고 sample_span_seconds와 실제 플레이 시간을 함께 확인한다.

2026-10-12 범위 갱신: **내 방(`room`) → 폐가(`AbandonedHouse`), 실제 강의실(`classroom`) → 폐교(`AbandonedSchool`)**로 고정한다. 두 공간의 스캔·실측을 수동 구조 데이터로 정리하고, 그 위치·크기에 맞는 테마 프리팹으로 재구성한다. 다른 사용자의 공간 지원과 같은 맵의 테마 선택 기능은 범위에 포함하지 않는다. 세부 계약은 [Method A 가이드](../VRShoot_Method_A_Codex_Guide.reviewed.md)를 따른다. 이 갱신은 문서 변경이며 테마 구현 완료나 Goal 재개를 뜻하지 않는다.

2026-09-18 · 현재 상태는 모든 게임 시험 미실행이다. 이 문서는 향후 시험 절차이며 통과 결과가 아니다.

## 1 시험 환경과 기록

EditMode는 발사 허용·탄약·체력·웨이브·기록 비교를 검사한다. PlayMode는 씬·물리 충돌·재시작·풀 수명을 검사한다. 실제 Quest Pro는 양손 조작·연속 이동·UI 가독성·양안 가림·Virtual Desktop 성능을 검사한다. 편집기의 평면 화면 시험으로 실제 기기 검증을 대체하지 않는다.

시험마다 빌드 식별자, 맵, 에디터·패키지·렌더러 버전, Windows OpenXR 런타임, Virtual Desktop 해상도·주사율·코덱·비트레이트·프레임 보간 상태, 측정 날짜를 기록한다. 한 번에 비교할 때는 같은 조건을 유지한다.

## 3 추가 경계 조건

- 빈 탄창과 장착 탄창 없음은 서로 구분하되 두 경우 모두 발사를 차단한다.
- 왼손 그립을 유지한 채 허리 보급에 접촉해도 프레임마다 탄창을 만들지 않는다.
- 삽입 이벤트 중복, 같은 적 사망 이벤트 중복, 회복 이벤트 중복은 한 번만 처리한다.
- 생성 실패·풀 고갈·NavMesh 경로 실패는 할당량을 소비하지 않는다.
- 적의 시스템 재배치는 처치 수를 늘리지 않는다. 복구 실패를 가짜 처치로 처리하지 않는다.
- 정지 중 실제 손을 움직이면 재개 시 보조 손잡이 접촉을 다시 검사한다.
- 저장 파일 없음·손상·권한 오류·지원하지 않는 스키마를 각각 시험한다. 원본 사용자 기록은 백업하고 시험 폴더를 쓴다.
- 클리어·사망 동시 발생 시 회복 후 부활하지 않는다. 결과 저장이 중복 실행되지 않는다.
- 앱 강제 종료 후 정상 기록 파일이 손상되지 않는지 확인한다. 종료 도중의 미완료 도전 복구는 이번 필수 기능이 아니다.

## 4 성능 시험

첫 목표는 72Hz, 앱 프레임 예산 약 13.89ms다. 전투 구간에서 CPU·GPU 각각의 p95 12.5ms 이하를 여유가 있는 초기 통과 기준으로 삼는다. CPU와 GPU 시간은 단순 합산하지 않는다. p99, 순간 멈춤, 앱 프레임과 스트리밍 지연을 함께 기록한다. 90Hz는 선택 목표이며 72Hz 검증 없이 먼저 약속하지 않는다.

Virtual Desktop의 해상도·72Hz·코덱·비트레이트를 고정한다. PC는 유선 네트워크 연결을 우선하고 사용 중인 무선 환경을 기록한다. 프레임 보간을 끈 측정을 기본 비교로 하되, 실제 플레이 설정에서 별도 결과도 남길 수 있다. 이 경우 서로 다른 조건임을 표시한다. [Virtual Desktop 안내](https://www.vrdesktop.net/)

| 측정 구간 | 조건 | 길이 |
|---|---|---|
| 빈 맵 | 적·효과 없는 상태, 정해진 동선 | 워밍업2분 뒤 3분 |
| 일반 전투 | 초기 웨이브, 재장전 포함 | 3분 |
| 최대 동시 수 | 방4·강의실6, 원거리 각 상한, 효과·탄창 포함 | 3분 |
| 지속 시험 | 실제 웨이브·반복 재장전·처치 | 각 맵 약5분 |
| 반복 전환 | 재도전과 맵 전환 각10회 | 모든 전환 완료까지 |

Unity Profiler로 CPU·GPU 구간과 GC를 조사하고, 최종 판정은 개발자 계측의 부담이 적은 빌드와 VR 런타임·Virtual Desktop 관측을 함께 사용한다. GPU 시간이 도구에서 제공되지 않으면 빈칸을 0ms로 기록하지 말고 해당 API에서 가능한 측정 수단을 바꾼다.

VRAM은 8GB 안에 데이터를 맞추되 사용량 한 수치만으로 안정성을 판단하지 않는다. 워밍업 후 주기적 회수에서 객체 수가 상한으로 돌아오고 VRAM·RAM이 계속 상승하지 않는지 확인한다. 06의 최대 객체 수를 초과하면 평균 FPS가 높아도 실패다.

## 5 플레이 경험 확인

본인 외 테스트 참여자가 가능하면 2~3명에게 짧게 플레이하게 한다. 통계적으로 검증된 UX 연구라는 주장은 하지 않는다. 처음 양손으로 발사하기까지 막힌 부분, 재장전 성공·실패 이유, 팔 UI 오독, 공격 예고 인지, 어지러움·불편감과 중단 시점을 기록한다. 불편하면 즉시 멈출 수 있어야 한다.

카메라 강제 흔들림을 쓰지 않고 속도 조절을 제공한다. 특정 설정이 모든 사용자에게 멀미를 없앤다고 단정하지 않는다. 시각 움직임과 신체 감각 불일치를 다룬 L09 강의 내용을 구현·평가에 연결한다.

## 6 기록 양식과 종료 기준

시험 결과 한 건에는 `시험 ID / 날짜 / 빌드 / 맵 / 환경 / 실행 절차 / 예상 / 실제 / 통과 또는 실패 / 증빙 경로 / 연결 결함`을 기록한다. 결함 한 건에는 `심각도 / 재현율 / 최소 절차 / 실제와 기대 차이 / 의심 범위 / 수정 / 재검증 결과`를 기록한다.

S0는 크래시·데이터 파괴·실행 불가, S1은 핵심 조작·생존 진행·기록 오류, S2는 읽기 어려움·경미한 외형·효과 문제로 분류한다. 최종 제출은 S0·S1을 해결하고 R01~R20을 검사한 상태로 한다. 남은 S2는 영향과 재현 조건을 알려 시연·보고서에 반영한다. 측정하지 않은 항목을 통과로 표시하지 않는다.

## Method A 추가 인수

각 맵의 고정 테마 매핑, 원본 없는 생성·빌드, 소유 루트만 안전하게 재생성, 실패 복구와 구조/앵커/NavMesh 불변을 검사한다. 서로 다른 두 맵의 배치가 같아야 한다는 시험은 만들지 않는다. Room의 복도·7앵커·1.5m/1.5초와 기존 전투 회귀를 보존한다. Classroom 미촬영 상태는 두 맵 완료가 아니다.
