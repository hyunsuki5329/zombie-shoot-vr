# 제출 자료와 실행 안내

2026-10-12 범위 갱신: **내 방(`room`) → 폐가(`AbandonedHouse`), 실제 강의실(`classroom`) → 폐교(`AbandonedSchool`)**로 고정한다. 두 공간의 스캔·실측을 수동 구조 데이터로 정리하고, 그 위치·크기에 맞는 테마 프리팹으로 재구성한다. 다른 사용자의 공간 지원과 같은 맵의 테마 선택 기능은 범위에 포함하지 않는다. 세부 계약은 [Method A 가이드](../VRShoot_Method_A_Codex_Guide.reviewed.md)를 따른다. 이 갱신은 문서 변경이며 테마 구현 완료나 Goal 재개를 뜻하지 않는다.

2026-09-18 · 이 문서는 실제 구현 뒤 제출 묶음을 완성하기 위한 절차와 작성 가능한 초안을 제공한다.

## 2 제안서 본문 초안

### 프로젝트명

현실 공간 촬영 기반 VR 좀비 생존 FPS

### 제작 목적

실제 공간을 스캔·실측하고 구조와 가구 배치를 수동 데이터로 정리하여 VR 게임 공간으로 재구성한다. 내 방은 폐가, 실제 강의실은 폐교 테마로 제작한다. 양손 조준과 왼손 탄창 교체를 통해 VR 컨트롤러에 맞는 조작을 구현하고, 구조 재구성뿐 아니라 충돌, 적 이동, 성능과 사용자 경험을 함께 평가한다. 내 방은 플레이 공간 확보를 위해 원본 배치를 유지한 채2.5배 확대한다.

### 주요 콘텐츠

플레이어는 방 또는 강의실을 선택하고 K2로 근접·원거리 좀비를 상대한다. 양손으로 총을 잡은 상태에서만 발사할 수 있으며, 재장전은 왼손으로 탄창을 제거하고 허리의 새 탄창을 삽입하는 방식이다. 웨이브가 끝나면 체력을 일부 회복하고 다음 전투를 준비한다. 사망 시 실제 도달 웨이브와 처치 수를 기록한다. 체력과 진행 정보는 오른팔 전완 UI에서 확인한다.

### 제작 방법

iPhone의 Scaniverse Classic 메시 스캔을 FBX로 내보내 Unity의 로컬 구조 참조로 사용한다. 실측과 수동 확인으로 벽·가구·출입구 데이터를 구성하고, 그 배치에 맞춰 테마 프리팹과 별도 충돌·NavMesh를 생성한다. 원본 스캔은 최종 빌드에서 제외한다. 스캔 복원 알고리즘 자체 개발이나 자동 공간 인식을 구현했다고 주장하지 않는다. Quest Pro와 Virtual Desktop으로 PC VR 실행을 검증하며, 게임 규칙은 공통화하고 맵별 외형·충돌·시작점·생성점만 분리한다. 외부 에셋과 동작의 출처 및 사용 조건을 기록한다.

### 평가와 결과물

평가는 양손 발사·수동 재장전의 일관성, 웨이브·기록 규칙, 구조 배치와 승인된 게임 배율의 대응, 공간 충돌과 적 경로, 오른팔 UI 가독성, 실제 기기 프레임 시간으로 구성한다. 목표 결과물은 두 맵을 포함한 게임, 소스, 실행 안내, 발표자료, 보고서와 시연 영상이다. 2026-10-14 현재 Room은 폐가 시제품이며, Classroom도 촬영 자료와 사용자 추정14×6.3m를 바탕으로 폐교 시제품을 구현했다. 강의실 학생 가구20조와 천장3m는 추정이고, 두 맵의 최신 VR 인수·성능 결과는 아직 대기 중이다. 다른 사용자의 방 지원과 자동 맵 생성은 프로젝트 범위에 포함하지 않는다.

제출 양식에 이름·학번·수업명 등의 필드가 있으면 작성자가 실제 정보를 입력한다. 개인정보를 추정해 넣지 않는다. 위 본문은 계획 단계의 서술이며 구현 성과나 실측 결과를 주장하지 않는다.

## 3 실제 실행 안내 작성 순서

1. 최종 빌드의 파일명·버전·날짜와 검증한 PC 사양을 적는다.
2. Quest Pro의 Virtual Desktop 앱과 PC Streamer 연결을 확인하고 검증한 OpenXR 런타임을 사용한다. 개인마다 런타임을 임의로 바꾸게 하지 않고 실제 성공한 설정을 명시한다.
3. PC 유선·무선 연결 조건과 해상도·72Hz 등 성능 시험 설정을 적는다.
4. 실행 파일을 열고 맵을 선택한다. 조작은 왼쪽 이동, 오른쪽 연속 회전, 양손 잡기 후 오른쪽 트리거, 왼손 재장전, 오른팔 UI로 안내한다.
5. 일시정지·재도전·맵 선택과 종료 방법을 안내한다. 실제 메뉴 버튼 바인딩을 기록한다.
6. 저장 위치와 맵별 기록의 의미를 적는다. 5웨이브 클리어 뒤 6에서 사망하면 `wave 6`이다.
7. 입력 불가, 한쪽 눈 이상, 프레임 저하, 기록 저장 실패는 성공한 환경 설정·오류 로그를 확인하는 순서로 안내한다.

소스 실행 안내에는 검증한 에디터 패치·필수 모듈·패키지 잠금·열어야 할 Bootstrap 씬·Windows 빌드 방법을 적는다. 생성되는 Library를 포함해 프로젝트 전체를 무작정 압축하지 않는다.

## 4 발표10분 이내 · 동작 영상3분 이내

사용자가 제공한 최신 공지 기준이다. 발표는 기획의도/요구사항, 팀 업무분장(팀인 경우), 일정/주요 이슈, 결과물 주요 특징, 실제 VR 동작 영상을 포함한다. 제안서는 제작 취지·요구사항/환경·기술적 특징·주단위 계획·결과물 형상·기대효과를 PPT로 작성해 PDF로 제출하고, 팀이면 분담1쪽을 추가한다.

## 5 결과보고서 구조와 모을 증빙

### 제작 목표와 범위

실제 공간 구조 기반 테마 맵과 VR 전투를 결합한 이유, 제작 기간, 두 맵·K2·근접/원거리 및 보스/크롤러 변형 범위를 설명한다. 다른 사용자의 공간 업로드는 범위에 포함하지 않는다.

### 수업 내용의 적용

L04의 게임 엔진 제작 흐름을 환경·상호작용·음향·시험에 연결한다. L08의 공간 크기·사용자 경험과 L09의 부작용 내용을 이동·회전·UI·시험 설계에 연결한다. 외부 스캔 도구의 역할과 직접 구현한 구조 데이터·테마 생성·충돌/경로·전투 통합을 구분한다. Gaussian Splatting은 최종 구현에 사용하지 않으며 적용했다고 쓰지 않는다.

### 공간 제작 과정

내 방→폐가, 실제 강의실→폐교를 각각 원본 스캔·실측 → 수동 구조 → 프리팹 배치 → 충돌/경로 → VR 전투 순서로 보여 준다. 실제 배치 보존과 게임용 확장을 구분한다. 외부 앱의 복원과 직접 구현한 구조·생성·게임 통합을 구분하고 미구현 테마는 완성 이미지로 제시하지 않는다.

### 게임 구현

양손 발사 조건, 탄창 소유권, 왼손 재장전, 좀비 공격과 NavMesh, 웨이브·회복·기록, 팔 UI의 구조를 설명한다. 상태 흐름 그림과 실제 코드 일부를 사용하되 파일 전체를 보고서에 붙이지 않는다.

### 시험과 결과

T01~T20의 통과·실패, 두 맵에서의 CPU·GPU 프레임 시간, 객체 수와 30분 시험, 실제 사용자 조작 문제를 제시한다. 표에는 버전·설정·측정 시간을 함께 적는다. 계획 목표값과 측정값을 다른 열로 구분한다.

### 한계와 확장

수동 구조 확인과 충돌·NavMesh 제작량, 원본 방의 좁은 전투 공간을2.5배 확대한 결정, 추정 가구 치수와 최종 미술·성능 검증의 한계를 적는다. 미실행 시험은 결과로 기재하지 않는다. 개선 방향은 현재 두 맵의 미술·경로·성능 및 사용자 경험으로 한정한다.

### 출처와 역할

본인이 작성한 코드·촬영·편집 작업, 사용한 무료 모델·애니메이션·효과, 스캔 앱과 오픈소스 렌더러를 구분한다. 외부 도구 사용은 실제 수업의 표기 규칙을 따른다.

## 6 최종 제출 전 확인

- [ ] 제출일·형식·파일 크기를 최신 공지로 확인했다.
- [ ] 실행 파일과 필요한 데이터 폴더가 함께 있다.
- [ ] 두 맵·양손 사격·왼손 재장전·두 좀비·팔 UI·기록을 최종 빌드에서 시험했다.
- [ ] 기록이 없는 첫 실행과 앱 재실행 모두 확인했다.
- [ ] 소스에 meta 파일과 잠금 패키지 버전이 있고 캐시·개인 경로·불필요한 촬영 원본이 없다.
- [ ] 실제 사용 에셋의 출처·사용 조건·소스 전달 방식을 확인했다.
- [ ] 보고서·발표의 수치와 화면이 최종 빌드 및 시험 기록과 일치한다.
- [ ] 장비 연결이 실패할 때 사용할 시연 영상을 별도로 재생해 보았다.
- [ ] 정상 동작하던 최종 빌드와 소스를 별도 위치에 백업했다.
