## 1 프로젝트 목표

아이폰으로 촬영한 내 방과 강의실을 VR 공간으로 재현하고, 플레이어가 K2를 양손으로 조준하며 좀비 웨이브를 버티는 Windows PC VR 게임을 완성한다. 현실 공간의 형태와 배치를 알아볼 수 있게 유지하고 전투 효과, 적의 공격 신호, 오른팔 UI를 더한다. 내 방은 폐가, 실제 강의실은 폐교로 개발자가 제작한다. 두 공간의 구조를 유지하는 것이 범위다.

완성의 기준은 두 맵에서 이동, 양손 사격, 왼손 재장전, 두 종류의 좀비, 웨이브 진행, 체력 회복, 사망과 기록 저장을 끝까지 플레이할 수 있는 실행 파일이다. 첫 1~2주에 촬영 결과의 VR 표시 가능성을 검증하고, 이후 작은 시험 공간에서 전체 게임 흐름을 연결한다. 이 순서로 공간 복원에만 시간을 쓰고 전투가 미완성으로 남는 상황을 방지한다.

## 3 플레이 규칙

왼쪽 스틱으로 부드럽게 이동하고 오른쪽 스틱으로 연속 회전한다. K2는 오른손에 계속 붙어 있다. 왼손이 총 앞부분을 잡고 있을 때만 오른손 트리거로 사격할 수 있다. 한 손 사격은 허용하지 않는다.

재장전은 왼손으로 앞부분을 놓고 탄창을 탈거하여 바닥에 버린 뒤, 허리에서 새 탄창을 꺼내 삽입하고 앞부분을 다시 잡는 순서다. 삽입하면 장전 준비는 완료되지만 앞부분을 다시 잡기 전에는 발사되지 않는다. 예비 탄창은 무한하며, 잔탄이 있는 탄창도 교체할 수 있다. 제거한 탄창의 잔탄은 회수하지 않는다.

최대 체력은 100이다. 웨이브가 끝날 때 일부 회복하고, 피격 직후 짧은 보호 시간을 둔다. 각 웨이브는 유한한 적 수를 갖지만 웨이브는 끝없이 이어진다. 사망하면 해당 도전을 종료한다. 오른팔 손목과 팔꿈치 사이 UI에 체력, 현재 웨이브, 처치 수를 표시한다.

기록은 실제 시작한 가장 높은 웨이브다. **5웨이브를 클리어하고 6웨이브에서 사망하면 결과와 최고 기록 후보는 `wave 6`이다.** 다음 웨이브의 준비 시간은 도달 기록에 포함하지 않는다. 맵별로 최고 도달 웨이브와 그 도전의 처치 수를 저장한다.

## 4 공간 제작 전략

첫 촬영은 Scaniverse Classic에서 작은 구역을 연속 스캔하고 로컬 처리·내보내기 가능 여부를 확인하는 방식으로 시작한다. 별도 복원용 원본은 서로 겹치는 일반 사진을 기본으로 보관한다. 일반 동영상은 보조 자료이며 앱 스캔과 같은 입력으로 가정하지 않는다. 촬영 설정과 동선, 재촬영 판정은 05 문서를 따른다.

스캔·실측에서 벽·바닥·큰 가구의 위치와 크기를 수동으로 정리한다. 구조·충돌·NavMesh와 최종 외형을 분리하고 내 방은 폐가, 강의실은 폐교 프리팹으로 구성한다. 구조 참조 원본은 로컬 편집 참조로 보존한다. 비교 빌드에는 별도 관찰용 가공 GS를 포함하며, 테마 전투 맵은 기존 구조·프리팹을 사용한다. 두 맵은 서로 다른 실제 공간의 구조를 사용한다. 세부 생성 계약과 시험은 Method A 가이드를 따른다.

## 7 1인 개발 운영

작업은 P01~P12 순서로 진행하되, 매 작업을 작은 실행 가능한 변화로 나누고 검증 후 저장한다. 주말에는 실제 Quest Pro 빌드를 실행하고 남은 결함을 정리한다. 월말까지 편집기에서만 테스트하는 방식은 피한다.

버전 관리에는 Assets, Packages, ProjectSettings와 모든 관련 meta 파일을 포함한다. Library, Temp, 캐시와 빌드 산출물은 제외한다. 원본 촬영 자료는 별도 백업하고 가공본과 구분한다. 외부 에셋은 출처와 사용 조건을 기록한다. 예산을 사용하는 구매·구독은 필요가 확인된 뒤 별도 결정한다.

초기 밸런스는 체력 100, 클리어 회복 20, 피격 보호 0.5초, 준비 시간 8초, 탄창 30발로 시작한다. 최대 체력과 탄창·조작 규칙 외의 수치는 테스트로 바꿀 수 있다. 효과나 적 수를 늘리기 전에 작은 방에서도 회피와 재장전이 가능한지 확인한다.

## 8 지연과 실패 대응

강의실 촬영이 늦으면 내 방 폐가와 공통 전투 작업을 먼저 진행한다. 누락된 벽·가구 치수는 실측으로 보완하고 추정값을 구분한다. 강의실 자료 없이 최종 두 맵 완료로 표시하지 않는다. 미술 작업이 늦으면 placeholder로 기능만 검증하고 최종 테마 완성 여부를 별도로 기록한다.

재장전이 어려우면 삽입 허용 거리·각도와 손잡이 위치를 조정한다. 수동 탈거·삽입, 양손 사격 조건은 유지한다. 성능이 부족하면 외형 데이터를 줄이고 적의 동시 수, 효과, 사체·탄창 수명을 조절한다. 적 두 종류와 두 맵을 삭제하는 것은 자동 대안으로 삼지 않는다.

우선 줄일 것은 복잡한 손가락 연출, 많은 효과 변형, 보조 통계, 세밀한 장식과 추가 사운드다. 핵심 기능을 바꿔야 할 정도로 시간이 부족하면 필요한 변경과 영향을 사용자에게 제시한다.

## 9 최종 완료 조건

두 맵에서 핵심 규칙 시험을 통과하고, 같은 실행 파일에서 맵 선택부터 사망·재시작까지 진행할 수 있어야 한다. 한 손 발사, 재장전 중 발사, 조기 웨이브 종료, 기록의 한 단계 오차, 벽을 통과하는 적 공격, 무한 오브젝트 누적을 막는다. 실제 기기에서 오른팔 UI를 읽을 수 있고 조작을 가리지 않아야 한다.

성능은 72Hz를 첫 검증 목표로 삼는다. 프레임 예산은 약 13.89ms이며, 측정 조건과 CPU·GPU 시간을 분리하여 기록한다. 기본 목표는 전투 구간에서 CPU·GPU 각각의 p95가 12.5ms 이하인 상태로 여유를 확보하는 것이다. 이는 실측 결과가 아니며 기기에서 확인 후 채택한다. 프레임 생성에 의존해 낮은 앱 프레임을 숨긴 결과는 동일 조건의 통과로 보지 않는다.

제출 묶음에는 Windows 실행 파일, 재현 가능한 Unity 소스, 환경과 실행 안내, 에셋 출처, 테스트 결과, 발표자료, 결과보고서를 포함한다. 시연 영상은 장비 연결 실패에 대비한 백업으로 준비한다. 구체적인 실행 순서와 체크리스트는 04, 08, 09 문서를 따른다.

4. P13-f: Room 체험 인수, 새 API에서 기존 두 전투 맵 회귀, 출처·복원·별도 빌드 패키징을 마친다.
5. 강의실 자체 GS가 준비되면 후속 적용한다. 사용자 담당 발표/영상과 보류된 성능 기록의 상태는 그대로 유지한다.

확정 기간은 자료 및 P13-a 결과가 나온 뒤 정한다. 호환성 실패를 낙관적으로 시간 추정에 숨기지 않는다. 기존 두 테마 게임의 성공과 새 GS 비교 기능의 성공을 별도 성과로 관리한다.
