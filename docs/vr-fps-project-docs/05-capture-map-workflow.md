## 먼저 선택할 촬영 방법

**이번 프로젝트의 첫 기술 시험은 Scaniverse Classic 앱에서 영상처럼 천천히 움직이며 연속 스캔하는 방식으로 진행한다. 일반 카메라로 복원용 원본을 따로 준비할 때는 서로 겹치는 사진을 기본으로 한다. 일반 동영상은 보조·대체 입력으로 둔다.**

책상 한 장, 침대 한 장처럼 서로 연결되지 않는 사진 몇 장을 찍는 방식은 사용하지 않는다. 같은 물체와 주변 구조가 다음 사진에도 반복해서 보여야 한다. Scaniverse 안에서의 스캔, 기본 카메라의 동영상, 일반 사진은 서로 다른 입력 경로다.

| 방법 | 장점과 부담 | 이 프로젝트의 기준 |
|---|---|---|
| Scaniverse 앱 내부 연속 스캔 | 앱이 이미지와 기기 위치·방향 정보를 함께 수집한다. 해당 앱의 처리·내보내기 기능에 의존한다. | 첫 작은 공간 검증에 우선 사용 |
| 겹치는 일반 사진 | 멈춰서 선명하게 찍기 쉽고, 원본을 별도 복원 도구에서 재사용할 수 있다. 동선·누락 면을 직접 관리해야 한다. | 일반 카메라 원본의 기본 방식 |
| 일반 4K 동영상 | 연속 동선을 기록하기 편하다. 흐린 프레임·비슷한 프레임을 골라내고 이미지로 추출하는 단계가 필요하다. | 사진 확보가 어려울 때의 대안 또는 공간 확인용 보조 |

선명도·원본 재사용을 고려한 사진 우선 선택은 이번 프로젝트의 판단이다. 어떤 방식도 복원 성공을 보장하지 않는다. COLMAP 공식 지침은 겹치는 시점, 일정한 조명, 실제 카메라 위치 변화와 영상 프레임 수 축소를 권한다. Scaniverse 공식 지침은 앱 스캔의 이미지·포즈 수집과 연속 이동을 설명한다. [COLMAP 촬영 원칙](https://colmap.github.io/tutorial.html) · [Scaniverse 촬영 원칙](https://www.nianticspatial.com/docs/scaniverse/techniques/)

## 1 제작 경로 선택

첫 실험은 방의 책상과 벽, 바닥이 함께 보이는 작은 구역으로 한다. Scaniverse Classic에서 촬영하고 앱 내 복원 결과를 파일로 내보내 Unity까지 가져오는 작은 한 사이클부터 검증한다. 공식 안내상 Classic은 개인·작은 공간의 스캔과 로컬 처리를 제공하며, 새 Scaniverse는 클라우드·조직 기능과 별도 요금제를 갖는다. 휴대폰에 설치된 앱 버전과 실제 내보내기 메뉴는 첫 시험에서 확인한다. [Scaniverse FAQ](https://www.nianticspatial.com/faq/scaniverse) · [현재 제품 구분](https://www.nianticspatial.com/docs/scaniverse/quickstart/)

기본 카메라로 찍은 MP4·사진 묶음을 Classic에 그대로 가져올 수 있다고 가정하지 않는다. 앱 내부 스캔을 선택했다면 그 앱에서 촬영한다. 일반 사진·영상은 사진 기반 복원이나 프레임 추출을 거치는 별도 경로용이다. 새 서비스의 다중 스캔 통합·촬영 시간 제한을 Classic에도 동일하게 적용하지 않는다. 앱이 원본 이미지·포즈를 외부로 내보내는지도 별도로 확인하며, 재사용이 필요하면 일반 사진 원본을 확보한다.

Scaniverse 메시 내보내기와 실측을 구조 참고 자료로 사용한다. 최종 맵에는 구조에 맞춘 게임용 프리팹·재질을 배치한다. P13에는 별도 GS 자료가 필요하다. COLMAP 비교·학습 파이프라인 자체 구축은 필수 경로가 아니다. 별도 복원이 필요할 때만 일반 사진·영상 경로를 사용한다.

아이폰 17 일반 모델에 후면 LiDAR가 있다는 전제로 계획하지 않는다. RGB 영상·사진 기반 복원을 준비한다. 일반 모델의 카메라 사양은 [Apple 공식 사양](https://www.apple.com/iphone-17/specs/)을 참고한다.

## 2 촬영 전 준비

- [ ] 방과 강의실의 사용 가능한 바닥 영역과 큰 가구를 간단히 그린다.
- [ ] 바닥 길이, 문 폭 등 기준 거리 2개 이상을 줄자로 재고 기록한다. 실제 크기를 기억에 의존하지 않는다.
- [ ] 이동 통로의 작은 물체와 흔들리는 물체를 정리한다. 촬영 도중 가구 위치를 바꾸지 않는다.
- [ ] 창문 빛과 실내 조명을 가능한 일정하게 유지하고 사람·모니터 움직임·거울 반사를 줄인다.
- [ ] 원본에 개인정보가 보이는 화면·종이·사진은 촬영 전에 정리한다. 촬영 가능한 시간과 공간 조건을 확인한다.
- [ ] 저장 공간·배터리를 확보하고 작은 시험 촬영을 먼저 복원해 초점·노출·출력 형식을 확인한다.

기준 거리에는 방의 벽 사이 길이와 문 폭 또는 책상 폭처럼 서로 다른 방향·위치의 길이를 선택한다. 숫자와 측정한 위치가 함께 보이도록 메모한다. 거울·유리·흰 벽은 어느 촬영 방식에서도 어려울 수 있다. 흰 벽만 화면 가득 찍기보다 모서리·문틀·고정 가구가 같이 보이게 한다. 움직이는 모니터 영상과 선풍기는 멈추고, 촬영 중 가구와 조명을 바꾸지 않는다.

### 2.1 일반 사진의 시작 설정

아래 설정과 숫자는 이 프로젝트의 시험 시작값이다. 제조사·복원 도구의 의무 조건이나 성공 보장 수치가 아니다. 앱 내부 스캔에서는 앱이 제공하는 설정과 화면 안내를 따른다.

| 항목 | 사진 촬영 기준 |
|---|---|
| 카메라 | 후면 메인 1×, 일반 사진 모드 |
| 해상도 | 24MP를 시작값으로 사용. 48MP 강제 촬영은 필요하지 않음 |
| 렌즈·배율 | 한 촬영 묶음에서 유지. 0.5×·2×·디지털 줌을 번갈아 사용하지 않음 |
| 촬영 동작 | 한 걸음 이동 → 잠깐 멈춤 → 흔들림이 가라앉으면 촬영 |
| 특수 모드 | 인물·파노라마·야간 장노출·필터 대신 밝은 환경의 일반 사진 사용 |
| 플래시·조명 | 플래시 없이 실내 조명을 일정하게 유지. 어두우면 먼저 조명을 보완 |
| 초점·노출 | 책상·벽의 윤곽을 확대 확인. 비슷한 거리에서는 잠금이 도움이 되지만 거리가 바뀌면 초점을 다시 확인 |
| 파일 | 원본 HEIF/JPEG 보존. 복원 도구가 HEIF를 못 읽으면 별도 JPEG 사본 생성 |

24MP·48MP 사진, HEIF/JPEG와 4K 30fps 영상 지원은 [iPhone 17 공식 사양](https://www.apple.com/iphone-17/specs/)에서 확인했다. 이 기능 목록 자체가 복원 품질 평가 결과는 아니다. 매우 가까이 접근해 렌즈가 자동 전환되면 뒤로 물러나 같은 렌즈를 유지한다. 꼭 필요한 다른 렌즈 사진은 별도 묶음으로 표시하고 동일한 카메라 보정값을 강제로 공유하지 않는다.

## 3 촬영 동선

1. 문틀·책상·바닥 모서리처럼 구분하기 쉬운 물체가 있는 곳에서 시작한다. 첫 프레임을 기억해 마지막에 같은 구역을 다른 위치에서 다시 담는다.
2. 방 안의 가능한 통로를 따라 이동하며 벽·가구가 겹쳐 보이도록 담는다. 방 가운데 서서 카메라만 한 바퀴 돌리는 촬영으로 끝내지 않는다.
3. 중간 높이의 벽·가구를 한 차례 담고, 카메라를 아래쪽으로 기울여 바닥·가구 다리·벽과 바닥 경계를 보충한다. 위쪽도 벽의 특징이 함께 보이도록 천장 경계까지 연결한다.
4. 책상·침대 주위에서 옆으로 위치를 바꿔 가구 옆면과 접근 가능한 뒷면을 담는다. 실제로 숙였을 때 볼 수 있는 책상 아래와 엄폐물 옆은 낮은 위치에서도 촬영한다.
5. 한 구역의 세부 촬영을 시작하고 끝낼 때는 이미 담은 넓은 장면을 포함한다. 책상만 가깝게 찍은 별개 묶음으로 고립시키지 않는다.
6. 누락된 바닥·문틀·가구 아래를 확인하고 시작 구역까지 연결해 마무리한다. 가구 뒤로 갈 수 없는 면은 억지로 촬영하지 않고 보수 대상으로 기록한다.

촬영 범위가 겹치고 다양한 위치에서 보이도록 하는 것이 중요하다. 흰 벽, 유리, 거울, 반복 무늬와 움직이는 대상은 복원이 어려울 수 있다. [공식 촬영 지침](https://www.nianticspatial.com/docs/scaniverse/techniques/)

### 3.1 Scaniverse 앱으로 할 때

앱 스캔 중에는 천천히 연속해서 움직인다. 화면의 추적·누락 표시를 확인하고 불안정해지면 속도를 줄여 이미 잘 담긴 문틀·가구 쪽으로 돌아온다. 첫 시험은 책상 한 개와 주변 벽·바닥으로 한정한다. 앱 내 결과에서 눈높이와 낮은 시점을 모두 확인한 뒤 파일을 내보낸다. 방 전체 촬영은 이 시험 결과를 Unity에서 확인한 후 진행한다.

구조 확인용 메시 모델과 텍스처를 함께 보관한다. 현재 방은 FBX를 확보했다. 실제 지원 형식·무료 범위·내보내기 여부는 휴대폰에서 확인하고 기록한다.

### 3.2 일반 사진으로 할 때

이전 사진에 있던 내용의 약 70~80%가 다음 사진에도 보이도록 시작한다. 이는 겹침을 확보하기 위한 프로젝트 목표이며 공식 고정 임계값은 아니다. 가까운 가구 옆에서는 이동 간격을 더 줄이고, 같은 면을 최소 3개의 서로 다른 위치에서 담는다. 사진마다 시선 방향을 조금 바꾸되 위치도 함께 바뀌어야 한다.

계획용 시작 분량은 작은 시험 구역 40~80장, 작은 방 전체 150~300장 정도로 잡는다. 장수보다 선명도·겹침·필요한 면의 확보가 우선이다. 부족한 면이 남으면 추가하고, 거의 동일한 사진은 처리용 사본에서 선별한다. 원본은 유지한다. 처음부터 방 전체 수백 장을 복원하기보다 작은 구역으로 도구와 PC 처리량을 검증한다.

사진을 찍을 때는 잠깐 멈추고, 앱 스캔은 연속 이동한다. 두 방식을 한 동작으로 혼동하지 않는다. 사진의 순서를 보존하고 세부 사진에도 주변의 공통 물체가 보이게 한다.

### 3.3 일반 동영상으로 할 때

영상만 촬영할 수 있다면 **후면 1×, 4K 30fps, 일반 동영상**을 시작 설정으로 한다. 액션·시네마틱·타임랩스 모드와 촬영 중 줌·렌즈 전환은 피한다. 앱에서 선택할 수 있다면 HDR 대신 SDR로 처리 경로를 단순화한다. 사진의 Smart HDR 설정을 끄라는 지시는 아니다.

사진과 같은 동선을 아주 천천히 이동한다. 한 클립에는 연결되는 한 동선을 담고 다음 클립의 시작에 이전 구역을 포함한다. 급격한 방향 전환과 흔들리는 구간은 복원용 이미지에서 제외한다. 60fps라는 이유만으로 선명도가 보장되는 것은 아니므로 조명과 실제 프레임을 먼저 확인한다.

복원할 때는 원본 영상에서 초당 약 2장을 추출하는 것으로 시작해 겹침·선명도를 보고 간격을 조절한다. 긴 영상의 모든 프레임을 무조건 투입하지 않는다. 흐린 구간에서 샘플링을 늘리는 것으로 해결하려 하지 말고 해당 구역을 다시 촬영한다. 원본 영상과 선별 이미지는 따로 보관한다. 이 추출 간격도 프로젝트 시작값이다.

### 3.4 촬영 직후 확인할 것

- [ ] 확대했을 때 문틀·책상 모서리가 뭉개지거나 이중으로 보이지 않는다.
- [ ] 시작·중간·끝 구역과 높이별 촬영 사이에 공통 물체가 보인다.
- [ ] 바닥·가구 옆·숙여서 볼 부분을 담았고 누락 면을 메모했다.
- [ ] 촬영 중 문·가구·사람·조명 변화가 없었는지 확인했다.
- [ ] 실제 길이 2개, 앱과 버전, 렌즈, 해상도, 촬영 회차를 기록했다.
- [ ] 작은 시험의 복원 결과가 열리고 PC로 복사할 수 있는 파일로 저장된다.

같은 물체가 두 겹으로 갈라지거나 큰 구멍이 생기면 해당 구간의 흐림·겹침·움직임을 먼저 확인한다. 사진 수나 영상 길이만 늘려 해결하려 하지 않는다. 기기에서 보이는 결과를 캡처하고, 성공/실패 이유를 P02 기록에 남긴다.

## 4 원본과 가공본 정리

```text
CaptureArchive/
  room/2026-09-촬영회차/
    originals/        원본 사진 또는 영상, 앱 스캔 백업(가능한 경우)
    selected-images/  복원에 쓸 사진 사본 또는 선별한 영상 프레임
    measurements.md   기준 거리, 조명, 촬영 구역
    exports/          앱에서 받은 가공 전 결과
    processed/        크기·원점·불필요 영역을 정리한 결과
    capture-notes.md  앱 버전, 출력 형식, 문제 구역
  classroom/촬영회차/
```

원본은 덮어쓰지 않는다. Unity의 별도 로컬 참조 씬에서 스캔을 확인하고 테마 씬에는 구조 데이터와 테마 자산을 포함하고, P13 관찰 씬에는 선택된 가공 GS만 별도로 포함한다. 실제 경로와 내보내기 도구·버전·날짜를 에셋 기록에 남긴다. G1용 실험 데이터와 제출용 맵 데이터를 구분한다.

PC로 옮길 때 파일 수·크기를 확인하고 임의 리사이즈나 메신저 압축을 거치지 않는다. HEIF 변환·이미지 축소·프레임 추출은 작업용 사본에 적용하고 변환 설정을 기록한다. 영상과 별도 사진을 합쳐 복원할 경우 같은 렌즈·해상도·보정값이라고 가정하지 않는다.

## 5 Unity 맵 제작

1. 작은 시험 결과를 import하고 Y축, 앞 방향, 바닥 높이와 원점을 정리한다.
2. 실측 길이 두 개를 비교해 1 Unity unit이 1m에 맞도록 전체 스케일을 보정한다. 두 번째 거리에서 큰 오차가 나면 복원 왜곡을 의심한다.
3. 벽·바닥·천장·큰 가구의 WorldSolid 충돌 구조를 만든다. 보이지 않는 잔여 메시가 이동을 막지 않게 한다.
4. 구조 데이터에 맞춰 Room은 폐가, Classroom은 폐교 프리팹을 생성한다. 외형의 위치·크기·바닥 접점과 충돌을 대조하고 양안 가림을 확인한다.
5. 좀비의 반지름·키·높이 차에 맞는 NavMesh를 굽는다. 책상 사이 좁은 곳과 막힌 구역을 검사한다.
6. PlayerSpawn은 바닥 위 자유 공간에 놓고 가구 내부나 문턱에 걸리지 않게 한다. 시작 시 HMD 높이와 시선 방향을 확인한다.
7. EnemySpawns를 여러 지점에 배치하고 플레이어까지 완전한 경로가 있는지 확인한다. NavMesh 위라도 닫힌 구역에 고립되면 사용할 수 없다.
8. 시각적으로 보이는 벽과 충돌이 맞는지 총알·투사체·이동으로 확인하고, 오류 구역은 원본 재촬영 또는 수동 보수한다.
9. 맵 ID를 `room` 또는 `classroom`으로 고정하고 공통 Combat 씬에서 불러온다.

## 6 G1 구조·테마 시험

- 실측 두 거리와 구조 크기를 비교한다. 첫 목표 오차 5% 이내로 확인하고 추정값은 별도 기록한다.
- 폐가 외형과 충돌의 벽·가구·문 통로 대응, 양안 가림, 탄환 차단을 확인한다.
- 반복 생성·실패 복구·사용자 오브젝트 보존을 시험한다.
- 원본 스캔 없는 복사본에서 구조와 허용 테마 자산으로 생성·빌드하고 의존성을 확인한다.
- 72Hz의 빈 맵·최대 동시 적 조건에서 08의 성능 기준으로 측정한다.
- 앱·구조 데이터·테마 자산·빌드 식별자와 실제 측정값을 남긴다. Placeholder 통과를 최종 테마 인수로 확대하지 않는다.

## 7 작은 방의 전투 적합성

방에서 최소 생성 거리와 회피 경로를 동시에 확보할 수 있는지 먼저 본다. 좁다고 현실 크기를 임의로 크게 늘리거나 적을 바로 옆에 생성하지 않는다. 촬영 전 통로 정리, 동시 적 수 감소, 공격 준비 시간 증가부터 시험한다. 현재 Room은 사용자 승인으로 약2.2×2.8m 게임용 복도와 폭1.4m 출입구를 추가했고 최소 생성 거리1.5m·예고1.5초를 사용한다. 이 확장 공간은 실제 스캔 영역과 구분하여 보존한다.

스폰 지점이 모두 막혔으면 생성을 잠시 보류하고 다른 지점을 찾는다. 10초 이상 조건을 만족하지 못하면 개발 로그에 지점·거리·경로 실패 이유를 남긴다. 할당량을 줄여 클리어시키는 방식으로 문제를 숨기지 않는다. 최종 맵은 여러 플레이어 위치에서 남은 적이 모두 생성될 수 있어야 한다.

## 9 P13용 GS 촬영·자료 준비

기존 FBX는 메시 구조 참조다. 확장자를 PLY로 바꾸거나 메시 점을 출력하는 것으로 촬영 기반 GS 결과를 얻었다고 표시하지 않는다. [공식 GS 안내](https://www.nianticspatial.com/docs/nsdk/how-to/ar/gaussian_splat/)와 휴대폰의 실제 지원 메뉴를 대조한다.

1. Scaniverse에 원본 세션이 남아 있는지 확인한다. 해당 앱 버전이 원본을 GS로 재처리할 수 있으면 그 경로를 시험한다. 지원 여부를 확인하지 않은 채 FBX 재처리를 약속하지 않는다. 불가능하면 GS 모드로 다시 촬영한다.
2. 첫 대상은 방이다. 관찰 지점에서 보일 문·책상·침대와 주변 바닥·벽을 연결되게 담고 모서리/뒤쪽 누락을 확인한다. 움직이는 화면·사람·반사는 줄인다. 게임에서 바꾼 가구 배치와 실제 촬영 상태의 차이를 기록한다.
3. GS 결과를 앱에서 여러 시점으로 확인하고 지원 PLY/SPZ로 내보낸다. 단순 RGB 점군 PLY와 Gaussian 속성 데이터는 구별한다. 카메라·앱 원본도 가능한 범위에서 별도 보관한다.
4. 경로·파일 크기·SHA256·촬영 날짜·앱 버전·처리/내보내기 설정, 기준 길이2개와 측정 위치를 기록한다. 현재 방4.3×3.5m와 강의실14×6.3m는 근사값이다.
5. 로컬 임포트로 바닥·축·단위·크롭·회전을 확인한다. 원본은 유지하고 가공본에 새 식별자를 부여한다. 기준 길이 오차와 특징3개의 대응을 기록한다.
6. 손/총·바이러스가 잘 보이는 정면 빈 공간을 정하고, 원본 크기 충돌과 관찰 앵커를 만든다. 최신 게임 씬을 일괄 재생성하지 않는다.

현재 공간2배·가구 기본1.5배 및 후속 수동 편집은 게임 쪽 규칙이다. 위2026-10-13의2.5배 설명은 과거 결정이며 현재값이 아니다. GS는 실제 크기 기준으로 보정하고 각 공간의 앵커를 따로 둔다. 원본 파일 경로를 확인하기 전 새 GS가 확보됐다고 기록하지 않는다.
