# 실제 방 맵 작업 기록

2026-10-12 사용자 요청에 따라 기존 Goal의 P02·P09를 재개한다. 원본은 사용자 제공 Scaniverse 2026-10-12 124954.fbx이며 약4.3m(옷장 벽 방향) ×3.5m(맞은편 벽까지)로 확인됐다. 수치는 대략 실측이며 VR 체감 보정이 남는다.

## 구현 계획과 판단

1. 원본은 보존하고 FBX·텍스처·처리 메시·NavMesh는 External/RoomScan에 로컬 복원한다. Git에는 생성 코드·씬·충돌 구성·출처·검증만 포함한다.
2. 메시의 벽 면적 분포로 기준 벽을 추정한다. X 약-2.075~2.105, Z 약-1.85~1.90m이다. 전체 bounds를 바로 압축하지 않고 이 벽 간격을4.3×3.5m에 대응한다. 높이는 스캔 약2.45m를 임시 기준으로 사용한다.
3. 누락 벽·천장은 단순 면으로 보완한다. 바닥·벽·침대·책상·의자·수납/건반 구역을 별도 단순 충돌로 구성한다. 복잡하고 깨진 메시 자체를 이동 충돌로 사용하지 않는다. 중앙 통행로의 고립 면 제거 필터를 적용했으나 이번 원본에서 제거된 삼각형은 0개다.
4. NavMesh, 플레이어 시작점, 적 후보점을 만들고 생존수4·원거리1을 유지하고, 아래 사용자 승인에 따라 최소 생성 거리는1.5m로 조정한다. 좁은 방의 회피 가능성은 실제 기기로 확인한다.
5. 기존 Bootstrap→Combat→Room 로더·전투·기록을 사용한다. Classroom은 아직 자료가 없으므로 비활성 상태를 유지한다. 실제 Room 로딩·경로·전투·정지·재시작·기록·반복 언로드를 자동 검증하고 Windows 빌드를 제공한다.

Ruling: 사용자가 메시 스캔을 제공하고 적용을 승인했으므로 GS 패키지를 새로 도입하지 않고 텍스처 메시 경로를 검증한다. P02의 양안 가림·성능 인수는 자동 테스트로 대체하지 않는다.
Ruling: 기존 미병합 PR #20의 전투 변경을 포함한 aa09561에서 방 작업 브랜치를 분기한다. 새 PR은 #20 브랜치를 base로 둔다. 원본과 집 내부 사진은 업로드하지 않는다.
Ruling: 사용자의 재개 요청 후 Goal 상태 active를 확인했다. 실제 기기 인수와 강의실·제출물이 남아 있으므로 전체 목표 완료로 표시하지 않는다.

## 완료 조건

방 선택이 활성화되고 실제 스캔 외형에서 공통 전투가 실행되는 빌드, 측정 기준과 보수 내역, 자동 검증 및 복원 안내를 제공한다. 실제 기기 T02/T11/T16/T17, 강의실 맵 및 최종 제출 작업은 별도 미완료로 남긴다.

## 적용 결과와 남은 확인

- 원본 15,286,000바이트, SHA256 `245bbdb7284d6b755125b131be681891173ba791be3cf27b429726a048e1b2e8`. 사용자 촬영본이며 타인의 스캔 모델을 사용한 것이 아니다. Scaniverse 복원 기능과 직접 만든 게임/충돌/경로 코드를 구분한다.
- 원본 텍스처8192×8192는 보존하고 Unity 표시 텍스처를4096×4096·mipmap·압축으로 설정했다. 원본135,226삼각형에서 출입문 개구부816개 삼각형을 제거해134,410삼각형이며, 생성 후보점은 실내5개·복도2개다.
- 바닥·벽·천장·가구의 단순 충돌과 스캔 외형을 분리했다. 누락된 벽/천장 및 책상 면은 단색 면으로 보완했다. 천장 높이2.45m와 가구 충돌은 추정값이며 실제 VR에서 보정해야 한다.
- 초기 플레이어와 가까운 적 후보점을 영구 제외하던 검증을 수정했다. 시작 시 최소1.5m 떨어진 후보가 하나 이상 있어야 하며, 실제 생성 순간에도 플레이어와1.5m 검사를 유지한다. 플레이어가 이동하면 이전에 가까웠던 지점도 사용할 수 있다.
- 최종 자동 검증 수치와 로그 해시는 [증빙](evidence/room-scan.json)을 따른다. 실제 Room 로딩·중앙 통로 생성·복도 경로·정지·사망 기록·재도전·10회 재로딩을 포함한다. 바닥 표본 검사는 연속 공간 전체의 전투 난이도나 실제 VR 인수를 대신하지 않는다.
- Quest Pro 양안 가림·스케일 체감·가구 우회·보스/크롤러·72Hz 성능 및30분 실기는 미실행이다. 강의실 자료도 아직 없다.

## Git 제외 자산 복원

기존 [외부 자산 복원](source-reproduction.md)과 [보스/크롤러 복원](boss-crawler.md)을 먼저 완료한다. 원본은 로컬에서만 보관한다. 새 체크아웃에서는 원본 FBX를 복사한 뒤 생성기를 반드시 실행해야 씬의 로컬 메시·재질·NavMesh 참조가 복원된다. 저장된 Room 씬만 열어서는 복원이 끝나지 않는다.

```powershell
python scripts/Restore-RoomScan.py --source 'C:/Users/User/Desktop/Scaniverse 2026-10-12 124954.fbx' --project 'D:/Unity Project/Zombie Shoot VR/Zombie Shoot VR'
```

같은 프로젝트를 연 에디터를 종료한 후 Unity6000.3.23f1에서 다음 순서로 실행한다. 실제 검증은 별도 캐시 복사본에서 수행하여 사용자 에디터 작업을 보존했다.

```powershell
& 'D:/Unity editor/6000.3.23f1/Editor/Unity.exe' -batchmode -quit -projectPath 'D:/Unity Project/Zombie Shoot VR/Zombie Shoot VR' -executeMethod VRFPS.Editor.ScannedRoomSetup.Configure -logFile room-configure.log
& 'D:/Unity editor/6000.3.23f1/Editor/Unity.exe' -batchmode -quit -projectPath 'D:/Unity Project/Zombie Shoot VR/Zombie Shoot VR' -executeMethod VRFPS.Editor.ScannedRoomSetup.Build -logFile room-build.log
```

각 프로세스의 종료와 `VRFPS_SCANNED_ROOM_CONFIGURED`/`VRFPS_ROOM_BUILD_SUCCEEDED` 로그를 확인한 뒤 다음 단계로 진행한다. 빌드는 Bootstrap·Combat·Room만 포함하고 Classroom은 비활성이다. 원본이 달라지면 복원 스크립트가 중단한다. 새 스캔은 재측정·보정·검증 후 적용한다.

## 사용자 승인 변경 · 2026-10-12

Ruling: 사용자가 방 최소 생성 거리1.5m와 방 밖 생성 공간을 함께 요청했다. Room만1.5m로 바꾸고1.5초 생성 예고 및 생성 직전 재검사를 유지한다. 출입문 쪽1.4m 통로와 약2.2×2.8m 게임용 복도를 추가한다. 복도는 촬영된 실제 방의 일부라고 주장하지 않는다. 비용: 좁은 공간의 체감 난이도는 실기 조정이 필요하다.

리뷰에서 중앙(.38,0,0)의 적 생성 중단을 발견했고 실제 PlayMode 시험에서 Alive=0으로 재현했다. 첫38점 탐색은 높이 허용 .06m로 일부 바닥을 놓쳤으므로 전체 보장 증빙으로 사용하지 않는다. 개선한 탐색은 높이 .25m, 수평 오차 .06m, 격자 .1m로 분리하고 복도까지 검사한다.

## 검토 처리

- 독립 리뷰의 중요 결함: 중앙 통로의 모든 생성점 거리 미달. PlayMode 중앙 위치 시험과 EditMode 바닥 표본 시험에서 실패를 확인했다. 사용자 승인 변경 후 EditMode74/74·PlayMode127/127 통과.
- 리뷰가 판단하지 않은 실기 편안함/양안/성능은 실제 기기 인수 전까지 미완료다. production 씬·자산 전달은 복사 후 해시로 확인한다. 무관한 OpenXR·학습 프레임워크 사용자 변경은 커밋에서 제외한다.
- 알려진 외형 한계: 스캔의 얇은 가구/상부 벽 손실과 출입구 절단 경계의 거친 부분이 남는다. 복도는 단색 임시 건축 외형이다. 실기 피드백에 따라 보수하며 완성된 시각 품질로 주장하지 않는다.
