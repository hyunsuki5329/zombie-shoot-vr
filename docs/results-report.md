# 현실 공간 촬영 기반 VR 좀비 생존 FPS — 결과보고서 초안

갱신일: 2026-10-07. 구현 기준: `524fa7b`. 이 문서는 개발 중간 결과를 설명하며 최종 제출본이 아니다. 실제 방·강의실, 새 외형의 기기 인수와 성능 측정이 남아 있다. 시험 수는 아래에 명시한 각 실행의 결과이며 이번 문서 작성 시 다시 실행한 수가 아니다.

## 1. 제작 목적과 범위

이 프로젝트는 익숙한 현실 공간을 이동 가능한 VR 게임 배경으로 만들고, 양손 조준과 직접 탄창 교체를 결합하는 것을 목표로 한다. Windows PC에서 게임을 실행하고 Quest Pro와 Virtual Desktop으로 표시·입력을 연결한다. 최종 콘텐츠 범위는 사전에 촬영한 방과 강의실 두 맵, K2 한 종류, 근접·원거리 좀비, 무한 웨이브다. 현장에서 공간을 자동 인식하거나 이용자가 촬영물을 즉시 업로드하는 기능은 포함하지 않는다.

현재까지 전투·입력·진행·메뉴·저장 규칙과 합성 시험장을 구현했다. 실제 공간은 아직 촬영 전이므로 현재 시험장을 현실 공간 복원 결과로 제시할 수 없다. Bootstrap의 실제 맵 선택 항목도 사용할 수 없는 상태로 유지한다. 따라서 이 결과는 전투 기반 구현의 성과이며 두 맵을 갖춘 완성 게임의 성과가 아니다.

## 2. 구현 환경과 구성

저장된 프로젝트는 Unity 6000.3.23f1을 사용한다. manifest의 주요 의존성은 XRI 3.5.1, URP 17.3.0, OpenXR 1.17.1, Input System 1.20.0, AI Navigation 2.0.14다. 소스 재현에는 에디터 버전뿐 아니라 Packages의 잠금 파일과 Assets의 meta가 필요하다. 구체적인 실행 명령은 [소스 복원 안내](source-reproduction.md)에 정리했다.

공통 전투와 맵 자원을 분리해 두 장소에서 같은 게임 규칙을 사용하도록 구성했다. Bootstrap은 선택과 전투 진입을 연결하고, 맵에는 외형·충돌·경로·시작점·생성점 정보를 둔다. 합성 씬으로 시작, 사망, 결과 저장, 맵 메뉴 복귀와 종료를 검사했다. 이것은 로딩과 수명 관리의 검증이며 실제 스캔 맵의 경로 품질이나 성능 검증은 아니다. [통합 증빙](evidence/p09-bootstrap.json)

## 3. 게임 상호작용 구현

### 양손 사격과 탄창 교체

K2는 오른손 고정을 전제로 하며 왼손 앞부분 잡기가 발사 조건에 포함된다. 탄창 교체는 앞부분 해제, 탄창 탈거, 폐기, 허리 보급, 새 탄창 삽입, 앞부분 재잡기 순서다. 새 탄창은 30발이며 제거한 탄창의 잔탄을 회수하거나 버린 탄창을 재사용하지 않는 규칙을 둔다. 탄창 상태와 소유권을 분리해 중복 삽입과 부적절한 재사용을 검사한다. [사격 규칙](evidence/p04-firing-rules.json), [수동 재장전](evidence/p05-manual-reload.json)

GAMGO의 K2와 STANAG 탄창을 확보한 뒤 기존 발사·재장전 앵커를 보존하고 외형을 교체했다. 축·단위 변환과 URP 재질 연결을 적용기로 재현한다. K2의 roughness를 smoothness로 변환해 metallic 맵의 알파에 넣으며 탄창 JPEG에는 알파가 없어 별도 smoothness 값을 사용한다. 실제 손 위치·탄창 삽입 감각과 양안 표시의 적합성은 아직 사용자의 검증을 받아야 한다. [외형과 복원 절차](gamgo-visual-restore.md)

### 적, 진행과 기록

적은 근접형과 원거리형으로 나뉘며 이동에는 NavMesh를 사용한다. 원거리 공격은 준비 동작과 투사체로 구성하고 벽의 차단을 검사한다. 사용자가 선택한 Yaku J Ignite를 근거리, Parasite L Starkie를 원거리 외형으로 연결했다. Scary Zombie Pack을 Humanoid로 리타게팅하고 평면 루트 이동을 추출해 NavMesh 위치와 외형이 분리되지 않게 했다. 원거리는 zombie scream을 준비 자세로 사용하며 피해·투사체는 기존 타이머가 결정한다. 별도 Zombie Reaction Hit은0.4초 상체 블렌드로 표현하고 연사·정지·사망·재사용을 처리한다. 평면 렌더와 자동 시험은 확인했으나 실제 VR의 크기·바닥 접촉·공격/피격 가독성·양안 품질은 미검증이다. [모델·동작 연결](evidence/p06-mixamo-visuals.json), [피격 반응](evidence/p06-hit-reaction.json), [자원 복원](mixamo-visual-restore.md). [공격 시험](evidence/p06-attacks.json), [이동 시험](evidence/p06-navigation.json)

웨이브는 각 회차의 생성 할당량과 동시 생존 수를 제한하면서 다음 회차로 이어진다. 생성 대기와 생존 적이 모두 없어야 클리어하며 사망과 클리어가 겹칠 때는 사망을 우선한다. 기록은 실제 시작한 최고 웨이브와 같은 도전의 처치 수를 함께 비교한다. 저장 파일의 손상·백업 복원·쓰기 실패를 처리하며 합성 씬에서 메뉴와 결과 흐름을 검증했다. 실제 두 맵의 앱 재실행까지 포함하는 인수는 남아 있다. [진행 규칙](evidence/p07-rules.json), [생성 제한](evidence/p07-spawning.json), [사망·클리어 수명](evidence/p07-lifecycle.json), [저장 기반](evidence/p08-records.json), [메뉴 통합](evidence/p09-bootstrap.json)

## 5. 공간 제작과 수업 내용의 적용 상태

방·강의실 촬영본과 기준 길이 두 개가 아직 없어 공간 복원·스케일 조정·충돌 제작·GS와 메시 비교의 결과는 제시하지 않는다. [촬영 지침](vr-fps-project-docs/05-capture-map-workflow.md)은 제작 방법을 정한 문서이며 수행 증빙이 아니다. 최종 보고서에는 실제 촬영 동선, 실측 길이, 사용 도구와 내보내기 형식, 같은 조건의 표시·가림·성능 결과를 넣어 표현 방식의 선택을 설명해야 한다.

로컬 강의 원문에서 아래 내용을 확인했다. 쪽수는 PDF의 첫 페이지를 1로 센 값이다. 강의가 다루는 개념과 프로젝트의 설계 연결을 설명하며, 수업에서 요구한 모든 실습을 수행했다는 의미는 아니다. 원본 파일 식별과 확인 범위는 [대조 기록](evidence/p12-course-mapping.json)에 남겼다. 강의 PDF 자체는 Git에 포함하지 않는다.

## 6. 출처, 기여와 한계

K2와 탄창의 제작자는 GAMGO이며 K2는 Free Standard, 탄창은 CC BY 4.0 조건으로 구분해 관리한다. 원본 모델·텍스처는 Git 추적에서 제외하고 사용자가 확보한 ZIP을 검증하는 복원 경로를 제공한다. 좀비 모델·동작은 Adobe/Mixamo에서 취득했으며 원본 파일의 해시를 확인해 로컬에 복원한다. 사용한 모션 팩과 별도 피격 클립을 구분해 기록했다. 폰트와 패키지 고지 수집은 진행됐지만 최종 빌드의 모든 의존 자산에 대한 배포 조건 검토는 완료되지 않았다. 정확한 모델 URL과 고지 원문은 [자산 출처표](asset-provenance.md)를 따른다.

사용자는 장비 연결과 일부 조작 실기 확인, 모델 선택과 다운로드를 수행했다. Codex를 통해 코드·검증·복원 도구와 문서를 작성했다. 이를 작성자 혼자 모든 원본 모델과 도구를 제작한 것으로 표현하지 않는다. 최종 제출의 AI 도구 표기 방식과 이름·학번·수업 정보는 실제 수업 규칙에 맞춰 확정해야 한다.

현재 가장 큰 한계는 실제 공간, 전체 기기 인수와 성능 수치가 없다는 점이다. 적 외형과 동작은 연결했지만 사용자는 새 빌드를 아직 실행 전이라고 답했으므로 자동 시험 결과를 실기 통과로 표시하지 않는다. 손 위치와 UI 가독성은 자동 시험으로 대체할 수 없다. 최종 결과보고서와 발표·시연 영상은 이 항목을 완성한 빌드에 맞춰 갱신해야 한다. 향후 자동 공간 제작은 복원뿐 아니라 스케일·바닥 추정, 충돌·NavMesh, 생성점 검증까지 해결해야 하므로 현재 달성한 기능으로 제시하지 않는다.
