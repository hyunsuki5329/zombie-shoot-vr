## 1. 제작 목적과 범위

이 프로젝트는 익숙한 현실 공간을 이동 가능한 VR 게임 배경으로 만들고, 양손 조준과 직접 탄창 교체를 결합하는 것을 목표로 한다. Windows PC에서 게임을 실행하고 Quest Pro와 Virtual Desktop으로 표시·입력을 연결한다. 최종 콘텐츠 범위는 사전에 촬영한 방과 강의실 두 맵, K2 한 종류, 근접·원거리 좀비, 무한 웨이브다. 현장에서 공간을 자동 인식하거나 이용자가 촬영물을 즉시 업로드하는 기능은 포함하지 않는다.

전투·입력·진행·메뉴·저장 규칙에 실제 방 구조 기반 폐가를 연결했다. Bootstrap에서 Room과 Classroom을 모두 선택할 수 있다. 합성 시험장, 이전 사진형 스캔 맵, 최신 폐가 맵의 결과를 구분한다. 두 맵을 갖춘 완성 게임의 인수는 아직 끝나지 않았다.

## 2. 구현 환경과 구성

저장된 프로젝트는 Unity 6000.3.23f1을 사용한다. manifest의 주요 의존성은 XRI 3.5.1, URP 17.3.0, OpenXR 1.17.1, Input System 1.20.0, AI Navigation 2.0.14다. 소스 재현에는 에디터 버전뿐 아니라 Packages의 잠금 파일과 Assets의 meta가 필요하다. 구체적인 실행 명령은 [소스 복원 안내](source-reproduction.md)에 정리했다.

공통 전투와 맵 자원을 분리해 두 장소에서 같은 게임 규칙을 사용하도록 구성했다. Bootstrap은 선택과 전투 진입을 연결하고, 맵에는 외형·충돌·경로·시작점·생성점 정보를 둔다. 합성 씬으로 시작, 사망, 결과 저장, 맵 메뉴 복귀와 종료를 검사했다. 이것은 로딩과 수명 관리의 검증이며 실제 스캔 맵의 경로 품질이나 성능 검증은 아니다. [통합 증빙](evidence/p09-bootstrap.json)

## 3. 게임 상호작용 구현

### 양손 사격과 탄창 교체

K2는 오른손 고정을 전제로 하며 왼손 앞부분 잡기가 발사 조건에 포함된다. 탄창 교체는 앞부분 해제, 탄창 탈거, 폐기, 허리 보급, 새 탄창 삽입, 앞부분 재잡기 순서다. 새 탄창은 30발이며 제거한 탄창의 잔탄을 회수하거나 버린 탄창을 재사용하지 않는 규칙을 둔다. 탄창 상태와 소유권을 분리해 중복 삽입과 부적절한 재사용을 검사한다. [사격 규칙](evidence/p04-firing-rules.json), [수동 재장전](evidence/p05-manual-reload.json)

GAMGO의 K2와 STANAG 탄창을 확보한 뒤 기존 발사·재장전 앵커를 보존하고 외형을 교체했다. 축·단위 변환과 URP 재질 연결을 적용기로 재현한다. K2의 roughness를 smoothness로 변환해 metallic 맵의 알파에 넣으며 탄창 JPEG에는 알파가 없어 별도 smoothness 값을 사용한다. 사용자는 후속 빌드에서 탄창 정렬, 버린 탄창10초 제거와 무기 음원을 확인했다. 최신 Room 빌드의 전체 조작·양안 인수는 남아 있다. [외형과 복원 절차](gamgo-visual-restore.md)

적은 근접형과 원거리형으로 나뉘며 이동에는 NavMesh를 사용한다. 원거리 공격은 준비 동작과 투사체로 구성하고 벽의 차단을 검사한다. 사용자가 선택한 Yaku J Ignite를 근거리, Parasite L Starkie를 원거리 외형으로 연결했다. Scary Zombie Pack을 Humanoid로 리타게팅하고 평면 루트 이동을 추출해 NavMesh 위치와 외형이 분리되지 않게 했다. 원거리는 zombie scream을 준비 자세로 사용하며 피해·투사체는 기존 타이머가 결정한다. 별도 Zombie Reaction Hit은0.4초 상체 블렌드로 표현하고 연사·정지·사망·재사용을 처리한다. 평면 렌더와 자동 시험은 확인했으나 실제 VR의 크기·바닥 접촉·공격/피격 가독성·양안 품질은 미검증이다. [모델·동작 연결](evidence/p06-mixamo-visuals.json), [피격 반응](evidence/p06-hit-reaction.json), [자원 복원](mixamo-visual-restore.md). [공격 시험](evidence/p06-attacks.json), [이동 시험](evidence/p06-navigation.json)

웨이브는 각 회차의 생성 할당량과 동시 생존 수를 제한하면서 다음 회차로 이어진다. 생성 대기와 생존 적이 모두 없어야 클리어하며 사망과 클리어가 겹칠 때는 사망을 우선한다. 기록은 실제 시작한 최고 웨이브와 같은 도전의 처치 수를 함께 비교한다. 저장 파일의 손상·백업 복원·쓰기 실패를 처리하며 합성 씬에서 메뉴와 결과 흐름을 검증했다. 실제 두 맵의 앱 재실행까지 포함하는 인수는 남아 있다. ### 실제 방 제작과 게임용 복도

사용자가 Scaniverse로 직접 촬영한 FBX를 사용했다. 원본에는 텍스처와 메시가 포함되어 있어 이번 경로에는 COLMAP이나 Gaussian Splatting 렌더러를 도입하지 않았다. 스캔 복원 알고리즘은 외부 앱의 기능이며 프로젝트 기여는 실측 약4.3×3.5m 보정, 별도 충돌체, 누락 벽/천장 보수, NavMesh/생성점, 공통 전투 통합 및 검증이다.

원본 스캔은 로컬 구조 참조로 보존하고, 구조 자산에서 외형·충돌·생성 위치를 분리했다. 초기 자체 제작 프리팹 시제품을 사용자가 실행한 뒤 공간이 작다고 피드백하여 전체를2.5배 확대했다. 후속 사용자 피드백으로 공간 배율을2배로 낮춰 현재 실내는8.6×7m이며 추정 천장은4.9m다. 가구는1.5배 기준으로 조정한 후 사용자가 개별 크기·위치·방향을 다시 편집했다. 현재 저장된 씬을 최종 배치 기준으로 사용한다. 복도는 원래2.2×2.8m의 게임용 추가 공간을 같은 비율로 확대한 것으로 실측 공간이 아니다. 플레이어·무기·적 크기는 유지했다.

초기2m 생성 제한은 중앙 통로에서 모든 후보를 제외했다. 독립 검토와 실패 시험으로 확인한 뒤 사용자 승인으로 Room만1.5m로 조정하고1.5초 예고를 유지했다. 실내5개·복도2개 생성점과 출입문 NavMesh를 연결했으며, 확대 후에도 이 규칙과 배치를 유지했다. [확대 검증](evidence/room-gameplay-scale.json).

이후 사용자가 선택한 Granny 모델에서 침대·책상·의자·선반·서랍장을 분리하고 기존 구조의 가구 영역에 맞췄다. 벽에는 낡은 도장 atlas 영역, 바닥에는 마루 텍스처를 적용했다. 원본 게임 집 전체를 옮긴 것이 아니며 외부 가구를 자체 제작했다고 주장하지 않는다. 현재 가구와 벽은 외형 메시 기준 충돌을 동기화하며, 추가 벽 누락을 수정했다. 바닥·천장 구조 충돌은 유지한다. [출처와 적용 과정](granny-house-assets.md).

5웨이브마다 Skeleton 보스,6웨이브 이후 일부 근접 슬롯에 Zombiegirl 크롤러를 배치한다. 크롤러 사망은 현재 자세에서1.05초 동안 옆으로 쓰러지며 정지/재개·재사용 상태를 처리한다. 자동 검증 결과와 실제 기기 인수를 구분한다. [보스/크롤러](boss-crawler.md), [사망 동작 증빙](evidence/crawler-death.json).

### 실제 강의실의 폐교 재구성

Scaniverse FBX를 로컬 참조로 사용하고, 사용자가 실제 공간에 없다고 표시한 세 돌출 영역은 파생 참조 메시에서 제외했다. 원본 파일은 보존했다. 스캔의 긴 방향을14m, 짧은 방향을6.3m로 맞췄으며 이 값은 사용자가 제공한 대략적인 크기다. 정밀 실측으로 표현하지 않는다.

kiyosueshi의 abandoned school에서 책상·의자·교탁·칠판·벽·바닥을 분리했다. UDIM 타일별 메시와 UV를 정리하고 URP 재질의 금속도·부드러움 채널을 원본 Metalness/Roughness에서 변환했다. 원본 학교 건물 배치를 복제한 것이 아니라 직접 촬영한 공간의 가구 구역에 재배치했다. 학생 가구는5구역×4조로 추정했으며 정확한 수를 스캔에서 식별했다는 뜻은 아니다.

가구에는 실제 외형 메시 기반 충돌체를 두고, 바닥·벽·천장은 구조 충돌체를 사용했다. NavMesh와8개 생성점을 검증하고 두 맵10회 전환·강의실 전투·기록 분리·재도전을 자동 검사했다. 학교 공간은 후속 요청으로2배인28×12.6m로 확장했고 가구는1.5배 기준 이후 사용자 편집을 반영했다. 출입구와 창문 상세는 미확정이며, 두 맵 이동·좀비 접근은 사용자 확인을 받았다. [배치 계획](classroom-map-plan.md), [원본 검사](evidence/classroom-scan-intake.json), [자산 출처](licenses/AbandonedSchool-Attribution.md).

## 5. 공간 제작과 수업 내용의 적용 상태

내 방 FBX와 약4.3×3.5m 기준을 확보하고 구조 데이터·2.5배 게임 공간·폐가 외형을 구현했다. 강의실도 스캔 참조에서 사용자가 지적한 세 돌출부를 제외하고 폐교 시제품을 구성했다. 가구20조와 천장3m는 추정값이며 실제 배치 인수는 남아 있다. GS/메시 비교를 수행한 것으로 제시하지 않는다. [촬영 지침](vr-fps-project-docs/05-capture-map-workflow.md)은 제작 방법을 정한 문서이며 수행 증빙이 아니다. 최종 보고서에는 실제 촬영 동선과 기준 길이, 구조 추정 부분, 게임용 확대 및 추가 공간을 구분하고 실제 양안·성능 결과를 보완해야 한다.

로컬 강의 원문에서 아래 내용을 확인했다. 쪽수는 PDF의 첫 페이지를 1로 센 값이다. 강의가 다루는 개념과 프로젝트의 설계 연결을 설명하며, 수업에서 요구한 모든 실습을 수행했다는 의미는 아니다. 원본 파일 식별과 확인 범위는 [대조 기록](evidence/p12-course-mapping.json)에 남겼다. 강의 PDF 자체는 Git에 포함하지 않는다.

## 6. 출처, 기여와 한계

K2와 탄창의 제작자는 GAMGO이며 K2는 Free Standard, 탄창은 CC BY 4.0 조건으로 구분해 관리한다. 원본 모델·텍스처는 Git 추적에서 제외하고 사용자가 확보한 ZIP을 검증하는 복원 경로를 제공한다. 좀비 모델·동작은 Adobe/Mixamo에서 취득했으며 원본 파일의 해시를 확인해 로컬에 복원한다. 사용한 모션 팩과 별도 피격 클립을 구분해 기록했다. 폰트와 패키지 고지 수집은 진행됐지만 최종 빌드의 모든 의존 자산에 대한 배포 조건 검토는 완료되지 않았다. 정확한 모델 URL과 고지 원문은 [자산 출처표](asset-provenance.md)를 따른다.

사용자는 장비 연결과 일부 조작 실기 확인, 모델 선택과 다운로드를 수행했다. Codex를 통해 코드·검증·복원 도구와 문서를 작성했다. 이를 작성자 혼자 모든 원본 모델과 도구를 제작한 것으로 표현하지 않는다. 최종 제출의 AI 도구 표기 방식과 이름·학번·수업 정보는 실제 수업 규칙에 맞춰 확정해야 한다.

현재 가장 큰 한계는 최신 두 맵의 전체 기기 인수와 성능 수치가 없다는 점이다. 강의실의 학생 가구 수·천장 높이·출입구/창문 상세도 확정되지 않았다. 이전 폐가를 사용자가 실행해 크기 개선을 요청한 사실과 최신 가구 교체 버전의 미확인 상태를 구분한다. 손 위치와 UI 가독성은 자동 시험으로 대체할 수 없다. Granny 업로드는 CC BY4.0을 표시하지만 업로더의 원 게임 자산 권한은 별도로 확인되지 않았다. 원본·추출 결과는 로컬에 보존하고 공개 배포 전 이 항목을 확인해야 한다. 최종 결과보고서와 발표·시연 영상은 실제 인수된 빌드에 맞춰 갱신해야 한다.

## 2026-10-07 실기 피드백 후속 수정

상기 피격 반응 빌드를 사용자가 실행하고 탄창 위치, 적 색조와 투사체 속도 개선을 요청했다. 후속 작업에서 탄창 소켓을 위 5mm·총구 쪽 2cm 이동하고, 적 색조를 제거하고, 투사체를 6m/s로 조정했다. 놓은 탄창은 10초 뒤 회수한다. 후속 자동 검증은 EditMode57/57, PlayMode117/117, Python23/23이다. [검증 증빙](evidence/vr-feedback-tuning.json). 이는 전체 실기 통과를 의미하지 않으며 수정 빌드의 실제 조작·양안·성능 확인은 남아 있다.
