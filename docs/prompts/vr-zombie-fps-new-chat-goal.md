## 7. 작업 단위별 Git 운영 — 실행 승인 범위

이 Goal 실행에서는 기존 저장소의 프로젝트 범위 내 **브랜치 생성, 커밋, push, PR 작성·갱신, 리뷰 확인·반영, 조건을 충족한 PR 병합과 최종 통합**을 승인한다. 구매·공개 전환·접근 권한 확대·LMS 제출은 별도다. 저장소와 대상은 위에 명시한 기존 저장소를 사용한다.

1. 한 단위는 목적과 검증 결과를 독립적으로 설명할 수 있는 변경으로 나눈다. 파일마다 PR을 만들거나 모든 기능을 거대한 PR 하나로 묶지 않는다.
2. 상태 확인 → 범위/완료 기준 → 구현 → 필요한 시험 → diff 검토 → 관련 파일·meta·문서만 commit → push → PR → 리뷰/실패 수정 → 재검증 → 병합 → 진행 기록을 수행한다.
3. 새 브랜치는 `codex/` 접두사를 쓴다. 병합된 브랜치에 후속 커밋만 push하고 새 변경도 병합됐다고 보고하지 않는다. PR의 실제 base/head와 의존 관계를 확인한다.
4. 미검증 실기가 남은 기능은 draft PR로 올리고 남은 항목을 명시한다. 아직 불가능한 검증을 통과로 바꾸어 병합하지 않는다. 해당 단위와 무관한 최종 발표/성능 대기가 모든 독립 PR의 완료를 막게 만들지도 않는다.
5. 리뷰 지적의 타당성을 확인해 수정하고 관련 시험을 다시 실행한다. CI나 외부 리뷰가 설정돼 있지 않으면 없다고 기록하며 가상의 승인을 만들지 않는다. PR 생성 후 채팅에 연결하는 도구가 있으면 첨부한다.
6. force push, hard reset, 무관한 사용자 변경 삭제, 보호 규칙 우회는 하지 않는다. 충돌은 실제 의도를 보존해 해결하고 재검증한다. 이미 병합된 이력을 재작성하지 않는다.
7. 최종 기본 통합 브랜치에 최신 게임과 P13이 들어갔는지 실제 diff·트리로 확인한다. 의존 브랜치에만 병합한 상태를 main 통합 완료로 표시하지 않는다. 필요한 통합 PR도 검증 범위를 명시한다.

각 단위 후 `docs/progress.md`에 소스/빌드 식별자, 변경 이유, 실행한 검증과 미실행 항목, PR URL/상태, 다음 작업을 기록한다. 자신의 최종 SHA를 넣기 위한 문서 커밋을 끝없이 반복하지 않는다.

## 8. 완료 조건과 대기 처리

다음 조건을 실제 증빙으로 모두 충족했을 때만 전체 Goal을 완료한다.

- 기존 두 테마 게임의 필수 기능을 유지하고 새 Room GS 비교 도입부를 구현·기기 인수했다. R01~R28/T01~T28의 필수 결과가 연결되어 있다.
- 새 기능과 새 API의 필요한 자동 시험·Windows 빌드·기존 전투 회귀를 통과하고 S0/S1 결함이 없다. 남은 S2는 영향과 재현 조건을 공개한다.
- 최종 실행 빌드, 정확한 실행 안내, 로컬 외부 자원 복원 자료, 재현 가능한 소스, 출처, 사실에 근거한 결과보고서가 준비됐다.
- 작업 단위의 커밋·push·PR·리뷰 지적을 정리했고 최종 통합 상태를 실제 원격에서 확인했다.
- 보류된 성능/약5분·반복 시험과 사용자 담당 발표/영상은 완료·면제로 추정하지 않는다. 전체 제출 완료 판정에는 해당 결과 또는 사용자의 명시적 기준 변경이 필요하다.

사용자 자료·기기 결과 없이는 더 진행할 수 없으면 가능한 독립 작업을 먼저 끝내고, 필요한 입력·시도한 방법·검증 결과·현재 재개 위치를 남긴다. 같은 상태를 확인하려고 시험·빌드·질문을 반복하지 않는다. Goal 도구의 blocked 조건에 도달했을 때 그 규칙에 따라 상태를 처리하며, 사용자 요청 없이 paused로 바꾸지 않는다. 보류 항목 때문에 완료하지 못한 것을 게임 구현 실패와 혼동하지 않는다.

진행 보고는 간결한 한국어로 현재 성과·다음 작업·필요 입력을 알린다. 최종 전달은 실행 파일 절대경로, 소스 SHA/빌드 GUID, 저장소·PR, 검증 결과, 알려진 한계, 실행/복원 방법을 포함한다.

**이제 현재 파일·Git·빌드·자료를 확인하고, 최신 상태에서 첫 미완료 단위부터 실행하라.**
